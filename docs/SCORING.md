# Automatic scoring methodology (BIPT v1.0)

This document describes **the historical, frozen v1.0 grading logic**, not a recommended universal standard for plant genetics. All official reported values were generated by code, with **no third-party LLM acting as a judge**.

> [!IMPORTANT]
> **The point totals are objective relative to this particular rubric—not a guarantee that every scientific judgment in the rubric is uniquely correct.** In particular, the top-candidate priority rule is debatable when case and control patterns conflict.

## 1. Per-instance scientific scoring: 93 points

| Key in the scoring JSON | Criterion | Maximum |
|---|---|---:|
| `key_annotation` | Per-ALT, per-transcript consequence correctness for selected difficult variants | 22 |
| `background_annotation` | Consequence labels for the remaining variants | 13 |
| `reference_qc` | Identifies a FASTA/VCF REF mismatch even if VCF says PASS; handles designated LowQual site | 7 |
| `genotype_qc` | REF match, PASS filter and number of unique high-confidence carriers across remaining records | 6 |
| `phased_primary` | Haplotypes disrupted and biallelic flag for the reference top candidate across all accessions | 13 |
| `phased_cis` | Correct non-biallelic classification of misleading cis mutations | 7 |
| `burden_background` | Disrupted haplotype counts for other genes | 3 |
| `gene_prioritization` | Primary gene (10), transcript (2), supporting-variant set overlap (2) | 14 |
| `interpretation` | Case/control biallelic counts (3), sample counts (2), inheritance model (1), no causal proof claim (2) | 8 |
| **Science per instance** | | **93** |

For tabular annotations, the grader keys on specified IDs, computes the **fraction of expected rows with the correct field value**, and multiplies by the point allocation. Score does not require exact output row order; a missing keyed row receives no credit for that item. Supporting-variant IDs use a **Jaccard overlap** on sets. The ranked top gene and its primary transcript have a fixed-match reward.

## 2. Aggregate score across three instances

All submitted pipelines must be rerun on the released input and two independently generated held-out inputs:

| Instance | Science maximum | Weight |
|---|---:|---:|
| Released (public) | 93 | 25% |
| Held-out 1 | 93 | 37.5% |
| Held-out 2 | 93 | 37.5% |

If `P`, `H1`, and `H2` are the three science scores, then:

```text
weighted_science = 0.25*P + 0.375*H1 + 0.375*H2
reexecution      = 2*valid_hidden1 + 2*valid_hidden2   # 0..4
artifact_check   = 2*valid_public_png + 1*valid_notes   # 0..3
raw_total        = round(weighted_science + reexecution + artifact_check, 2)
score            = minimum(raw_total, any triggered score cap)
```

Maximum total is `93 + 4 + 3 = 100`.

**`valid_hidden` here means successful execution plus the required files existing**, not a correctness threshold. Models can receive their re-execution points while making an incorrect scientific conclusion.

The only image checks are a valid PNG of at least **850 × 450 pixels**, at least **8 KB**, and sufficient grayscale variance. The notes requirement is a Markdown file with at least **120 non-whitespace characters**. Neither test measures the scientific accuracy of a figure's labels or its aesthetics.

## 3. Critical scientific error caps

The scorer applies the lowest triggered upper limit to the otherwise calculated score:

| Trigger | Maximum final score |
|---|---:|
| States that variant co-segregation / annotation **has established causal proof** | 65 |
| Incorrect top candidate on **at least two of three instances** | 69 |
| Both held-out cases fail to produce complete required deliverables | 55 |

These caps are triggered by **specified structured fields and execution status**, not by ad hoc textual judgment.

## 4. Reference algorithm and its scientific boundary

Historical reference code identifies a **severe primary-transcript variant** when its consequence belongs to:

```text
stop_gained
frameshift
start_lost
```

Qualifying variant sites must have **matching genomic REF and `FILTER=PASS`**. Genotype evidence is high confidence at `DP >= 10` and `GQ >= 20` and uses **phased diploid GT** for definite disrupted-haplotype counting. `0|1` across two separate sites may indicate cis or trans depending on *which* haplotype carries the change. Unphased genotypes are not automatically assumed to be trans.

A genetic candidate's reference priority is sorted by:

1. **Descending number of pale accessions with predicted biallelic disruption**.
2. **Ascending number of green accessions with predicted biallelic disruption**.
3. **Descending number of pale accessions with any predicted disrupted haplotype**.

The first key dominates the second; therefore, a gene with more affected accessions can outrank a gene with fewer cases but cleaner exclusion from unaffected controls. This is a **reasonable deterministic exercise rule but not the only scientifically defensible ranking rule**.

> [!WARNING]
> In held-out instance 1, several agents selected an alternative candidate emphasizing **specificity to the affected phenotype**. The fixed-answer grader penalized those selections even though they are **not necessarily careless or biologically incoherent**. See [Limitations](LIMITATIONS.md). The score measures conformance to the original rubric, not a proof of a uniquely correct prioritization strategy.

## 5. Publication-specific handling of missing submissions

The uploaded GPT-5.6 Luna Light archive did not contain an analysis runner or output; its internal scorer result was **0.00** because the required work product was absent. The public leaderboard labels this entry **N/A — no valid deliverable**. It is **excluded from the ten-valid-submission mean and spread**. Do not report its absence as an observed model error rate.
